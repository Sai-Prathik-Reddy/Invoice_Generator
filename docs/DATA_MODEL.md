# INGEN — Data Model

This document is the **contract** for every persisted entity and for the Template Definition JSON. In code, these are implemented as **zod schemas** in `src/core/schema/`, and all TypeScript types are inferred from those schemas (`z.infer`). If this document and the code disagree, fix one of them in the same PR.

---

## 1. Conventions

| Concept | Rule |
|---|---|
| IDs | Prefixed ULID: `cmp_`, `cli_`, `itm_`, `tpl_`, `tpv_`, `doc_`, `ast_`, `blk_`, `row_`, `col_`. Generated by `core/id.ts → newId('doc')` |
| Money / quantities / rates | **Decimal strings**, for example `"1250.50"`, `"18"`, `"2.5"`. Never JS numbers |
| Dates | ISO date `"2026-10-18"` for business dates; epoch ms (`number`) for `created_at` / `updated_at` |
| Coordinates | PDF points (`number`), 1 pt = 1/72 inch |
| Field keys | `snake_case`, `^[a-z][a-z0-9_]{0,39}$`, unique per template |
| State codes | Two-digit GST state codes as strings (`"36"` = Telangana, `"29"` = Karnataka, `"97"` = Other Territory) |
| Timestamps | Every table has `created_at` and `updated_at` |

```ts
type ID<P extends string> = `${P}_${string}`;
type Decimal = string;          // validated by /^-?\d+(\.\d+)?$/
type ISODate = string;          // YYYY-MM-DD
type EpochMs = number;
```

```ts
interface Company extends Timestamps {
```

### 3.4 Template & TemplateVersion
```ts
interface Template extends Timestamps {
  id: ID<'tpl'>;
  company_id: ID<'cmp'> | null;     // null = starter/global template
  name: string;                      // "GST Tax Invoice"
  doc_type: DocType;
  draft_definition: TemplateDefinition;   // working copy edited by the builder

  has_unpublished_changes: boolean;
  thumbnail_asset_id?: ID<'ast'>;
  archived: boolean;
}

type DocType = 'tax_invoice' | 'bill_of_supply' | 'quotation' | 'estimate'
             | 'proforma' | 'receipt' | 'credit_note' | 'delivery_challan'
             | 'prescription' | 'custom';

interface TemplateVersion {        // IMMUTABLE — write once
  id: ID<'tpv'>;
  template_id: ID<'tpl'>;
  version_no: number;               // 1, 2, 3 …
  definition: TemplateDefinition;   // deep-frozen at publish
  definition_hash: string;          // SHA-256 of canonical JSON (dedupe/integrity)

}
```

### 3.5 Document (invoice, quotation, …)
```ts
interface DocumentRecord extends Timestamps {
  id: ID<'doc'>;
  company_id: ID<'cmp'>;
  template_id: ID<'tpl'>;
  template_version_id: ID<'tpv'>;
  doc_type: DocType;
  status: 'draft' | 'finalized' | 'cancelled';

  // numbering (set at finalize)
  series: string;                    // from template config.sequence.series, e.g. "INV"
  number?: string;                   // rendered, e.g. "INV/26-27/0042"
  seq_value?: number;                // 42
  period?: string;                   // "2026-27" | "2026-10" | "all"

  issue_date: ISODate;
  due_date?: ISODate;
  client_id?: ID<'cli'>;
  place_of_supply?: string;          // state code; drives CGST/SGST vs IGST

  // user input (keys = Field Registry keys)
  values: Record<string, string>;                // document-scope fields
  items: Array<Record<string, string>>;          // line_item-scope fields per row

  // frozen at finalize (drafts recompute live)
  computed?: ComputedResult;
  snapshot?: {
    company: Company;
    client?: Client;
  };
  pdf_asset_id?: ID<'ast'>;

  // listing denormalisations (kept in sync by repo)
  grand_total: Decimal;              // "0" for drafts until computed
  client_name?: string;

  payment: {
    status: 'unpaid' | 'partial' | 'paid' | 'na';   // 'na' for quotations etc.
    paid_amount: Decimal;
    entries: Array<{ id: string; date: ISODate; amount: Decimal; mode: 'cash'|'upi'|'bank'|'card'|'cheque'|'other'; reference?: string }>;
  };

  converted_from_id?: ID<'doc'>;     // quotation → invoice lineage
  finalized_at?: EpochMs;
  cancelled_at?: EpochMs;
  cancel_reason?: string;
}

interface ComputedResult {
  doc: Record<string, Decimal | string>;            // document-level computed keys
  items: Array<Record<string, Decimal | string>>;   // per-row computed keys
  summaries: {
    tax?: Array<{ rate: Decimal; taxable: Decimal; cgst: Decimal; sgst: Decimal; igst: Decimal; total_tax: Decimal }>;
    hsn?: Array<{ hsn_sac: string; taxable: Decimal; rate: Decimal; cgst: Decimal; sgst: Decimal; igst: Decimal; total_tax: Decimal }>;
  };
}
```

**Mutability rules**

| Status | Editable fields |
|---|---|
| `draft` | Everything; can be deleted |
| `finalized` | Only `payment`. It can transition to `cancelled` |
| `cancelled` | Nothing. The number stays reserved and the PDF shows a "CANCELLED" watermark (re-rendered and stored as a new asset) |

### 3.7 Asset
```ts
interface Asset {
  id: ID<'ast'>;
  kind: 'image' | 'pdf' | 'font' | 'thumbnail';
  mime: string;                      // "image/png", "application/pdf"
  size: number;                      // plaintext byte size
  hash: string;                      // SHA-256 (Vault off) or HMAC-SHA-256 with vault key (Vault on) — dedupe
  blob: Blob;                        // plaintext Blob, or ciphertext Blob when Vault on
  width?: number; height?: number;   // images (px), for aspect-ratio locking
  created_at: EpochMs;
}
```
Assets are **write-once**. "Replacing a logo" creates a new asset and updates `company.logo_asset_id`. The old asset stays alive while any template version or document snapshot references it. GC removes it once it's unreferenced.

### 3.8 Settings (key/value)
```ts
type SettingsKey = 'ui' | 'session' | 'vault' | 'backup' | 'onboarding';

interface UiSettings { theme: 'dark' | 'light' | 'system'; density: 'comfortable' | 'compact'; reduce_motion: boolean }
interface SessionSettings { active_company_id?: ID<'cmp'> }
interface BackupSettings { last_backup_at?: EpochMs; reminder_days: number /* default 7 */ }
interface OnboardingSettings { completed: boolean; step?: string }
interface VaultSettings {          // see features/12-security-vault.md
  enabled: boolean;
  kdf: { algo: 'PBKDF2'; hash: 'SHA-256'; iterations: number; salt: string /* b64 */ };
  wrapped_dek_password: { iv: string; ct: string };
  biometric?: { credential_id: string; prf_salt: string; wrapped_dek: { iv: string; ct: string } };
  auto_lock_minutes: number;       // default 5
  verifier: { iv: string; ct: string };   // encrypts a known constant; fast wrong-password check
}
```
`vault` and `onboarding` are always stored in plaintext. The vault record has to be readable *before* unlock.

### 4.1 Page & Theme
```ts
interface PageSetup {
  size: 'A4' | 'A5' | 'LETTER' | 'THERMAL_80' | 'CUSTOM';

  width: number; height: number;    // pt; A4 = 595.28 × 841.89; THERMAL_80 width = 226.77, height grows

```
Blocks refer to theme colours as `"theme.primary"`. They may also use a literal hex value.

### 4.2 Config
```ts
interface TemplateConfig {
  currency: 'INR';
  locale: 'en-IN';
  tax_mode: 'exclusive' | 'inclusive' | 'none';
```

### 4.3 Field Registry
```ts
interface FieldDef {
  key: string;                       // snake_case, unique
  label: string;
  type: FieldType;
  scope: 'document' | 'line_item';
  required: boolean;
  default?: string;                  // may contain tokens like "{{today}}"
  placeholder?: string;
  help?: string;
  options?: string[];                // select / multiselect
  validation?: { min?: Decimal; max?: Decimal; pattern?: string; max_length?: number };
  catalog?: CatalogBinding;          // autocomplete
  system?: boolean;                  // true = created by a preset; label editable, key locked
  group?: string;                    // form section heading: "Bill To", "Shipping", "Other"
  order: number;
}

type FieldType = 'text' | 'multiline' | 'number' | 'money' | 'percent' | 'date'
               | 'select' | 'multiselect' | 'boolean' | 'phone' | 'email'
               | 'gstin' | 'state' | 'image';

interface CatalogBinding {
  source: 'clients' | 'items';
  match_on: 'name';
  fills: Record<string, string>;     // field key → catalog path, e.g. { client_gstin: "gstin", rate: "rate" }
}
```

**Reserved (system) context keys.** These are always available in tokens and formulas and can't be used as field keys:

| Namespace | Examples |
|---|---|
| `company.*` | `company.name`, `company.gstin`, `company.address.state_code`, `company.upi.vpa`, `company.custom.<key>` |
| `client.*` | `client.name`, `client.gstin`, `client.billing_address.city`, `client.custom.<key>` |
| `doc.*` | `doc.number`, `doc.issue_date`, `doc.due_date`, `doc.place_of_supply`, `doc.status`, `doc.type_label` |
| `page.*` | `page.number`, `page.total` (resolved in the PDF worker only) |
| `today` | Current date |
| `items` | The line-item collection (in aggregates) |

### 4.5 Layout
```ts
interface Layout {
  zones: {
    header: FixedZone & { height: number };
    footer: FixedZone & { height: number };

  keep_together: boolean;            // wrap={false}
  min_presence_ahead?: number;       // pt
  visible_if?: string;               // formula returning boolean
}
```

### 4.6 Blocks
```ts
type Block =
  | TextBlock | FieldPairBlock | ImageBlock | ShapeBlock | DividerBlock | SpacerBlock
  | TableBlock | TotalsBlock | TaxSummaryBlock | HsnSummaryBlock
  | UpiQrBlock | SignatureBlock | CustomKvBlock | BankDetailsBlock;

interface BlockBase {
  id: ID<'blk'>;
  type: Block['type'];
  name?: string;                     // layer name in builder
  style: BlockStyle;
  visible_if?: string;
  locked?: boolean;                  // builder: prevent move
}

interface BlockStyle {
  font_size?: number; font_weight?: 400 | 500 | 600 | 700; italic?: boolean;
  color?: string;                    // "theme.text" | "#111827"
  align?: 'left' | 'center' | 'right' | 'justify';
  line_height?: number;
  letter_spacing?: number;
  text_transform?: 'none' | 'uppercase';
  background?: string;
  padding?: [number, number, number, number];
  border?: { width: number; color: string; radius: number; sides?: ('t'|'r'|'b'|'l')[] };
  opacity?: number;
}

interface TextBlock extends BlockBase { type: 'text'; content: string }        // supports {{token | pipe}} and **bold**
interface FieldPairBlock extends BlockBase { type: 'field_pair'; label: string; value: string; layout: 'inline' | 'stacked'; label_width?: number }
interface ImageBlock extends BlockBase { type: 'image'; source: { kind: 'asset'; asset_id: ID<'ast'> } | { kind: 'company_logo' } | { kind: 'field'; field_key: string }; fit: 'contain' | 'cover' }

interface DividerBlock extends BlockBase { type: 'divider'; thickness: number; color: string; dashed?: boolean }
interface SpacerBlock extends BlockBase { type: 'spacer'; height: number }

interface TableBlock extends BlockBase {
  type: 'table';
  columns: Array<{
    id: string;
    header: string;
    value: string;                   // token, e.g. "{{item_name}}" or "{{line_total | money}}"
    width: number;                   // relative weight
    align: 'left' | 'center' | 'right';
  }>;
  show_serial: boolean;
  header_style: BlockStyle;
  row_style: BlockStyle;
  striped: boolean;
  repeat_header: boolean;            // default true
  min_rows?: number;                 // pad with empty rows for printed forms
}

interface TotalsBlock extends BlockBase {
  type: 'totals';
  rows: Array<{ label: string; value: string /* token */; emphasis?: boolean; visible_if?: string }>;
  show_amount_in_words: boolean;
}

interface TaxSummaryBlock extends BlockBase { type: 'tax_summary' }
interface HsnSummaryBlock extends BlockBase { type: 'hsn_summary' }
interface UpiQrBlock extends BlockBase { type: 'upi_qr'; amount_key: string /* "grand_total" */; caption?: string; size: number }
interface SignatureBlock extends BlockBase { type: 'signature'; source: 'company_signature' | 'none'; caption: string /* "Authorised Signatory" */ }
interface CustomKvBlock extends BlockBase { type: 'custom_kv'; source: 'company' | 'client'; columns: 1 | 2 }
interface BankDetailsBlock extends BlockBase { type: 'bank_details'; title: string }
```

### 4.7 Token & pipe syntax (in `content`, `value`, `label`)
```
{{ key }}                         → raw value
{{ key | money }}                 → ₹1,25,000.00
{{ key | money:nosymbol }}        → 1,25,000.00
{{ key | number:2 }}              → 1,25,000.00 (Indian grouping)
{{ key | percent }}               → 18%
{{ key | words }}                 → Rupees One Lakh Twenty-Five Thousand Only
{{ key | date:'DD MMM YYYY' }}    → 18 Oct 2026
{{ key | upper }} / lower / title
{{ key | default:'—' }}
```
Unknown keys are flagged in the builder at design time. At render time they print as an empty string, and dev builds log a warning.

## 5. Dexie Schema

```ts
// src/db/schema.ts
db.version(1).stores({
  companies:        'id, archived, updated_at',
  clients:          'id, company_id, [company_id+updated_at], [company_id+use_count]',
  items:            'id, company_id, [company_id+updated_at], [company_id+use_count]',
  templates:        'id, company_id, doc_type, archived, updated_at',
  templateVersions: 'id, template_id, [template_id+version_no]',
  documents:        'id, company_id, status, doc_type, [company_id+status], [company_id+issue_date], [company_id+doc_type+issue_date], template_version_id, client_id, number',
  sequences:        'id, company_id',
  assets:           'id, kind, hash, created_at',
  settings:         'key',
});
```

**Search strategy**
- With the Vault off, repositories use `filter()` with prefix and contains matching on `name`. That's fast enough for small-business volumes (under ~50k rows).
- With the Vault on, sensitive fields (names, amounts) are encrypted, so search and the dashboard run on an **in-memory decrypted cache**. The cache is built after unlock and kept in sync by the repositories.
- `name` is deliberately **not indexed**, so the same code path works in both modes.

### 5.1 Encrypted record envelope (Vault on)
```ts
interface EncryptedEnvelope<TIndex> {
  // plaintext index fields only (per table, see below)
  ...TIndex;
  _enc: { v: 1; iv: string /* b64, 12 bytes */; ct: string /* b64 AES-GCM ciphertext+tag of JSON payload */ };
}
```
| Table | Plaintext index fields |
|---|---|
| companies | `id, archived, updated_at` |
| clients / items | `id, company_id, updated_at, use_count` |
| templates | `id, company_id, doc_type, archived, updated_at` |
| templateVersions | `id, template_id, version_no` |
| documents | `id, company_id, status, doc_type, issue_date, template_version_id, client_id, updated_at` |
| sequences | everything (holds no sensitive data) |
| assets | `id, kind, created_at, hash (HMAC)`; the `blob` holds ciphertext |
| settings | `vault`, `onboarding` stay plaintext; others are encrypted |

> [!NOTE]
> With the Vault on, `documents.number`, `grand_total` and `client_name` move inside `_enc`. Documents are looked up by number through the in-memory cache.

## 6. Migrations

**Two independent version tracks:**

1. **Database version** (`db.version(n)`): Dexie upgrade functions for table/index changes.
2. **Template `schema_version`**: a pure upgrade chain in `core/schema/migrations.ts`:
   ```ts
   const migrations: Record<number, (d: any) => any> = { 1: (d) => ({ ...d, schema_version: 2, /* … */ }) };
   export function upgradeDefinition(def: unknown): TemplateDefinition { /* loop until CURRENT, then zod.parse */ }
   ```
   - Runs **on read**: when loading a template version, rendering, or importing a backup.
   - The stored immutable version is never rewritten.
   - Every migration has a fixture test (`v1.fixture.json → v2`).
